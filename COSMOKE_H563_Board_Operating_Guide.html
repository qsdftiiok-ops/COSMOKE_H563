COSMOKE · Voltage / Current Sensor Module

NUCLEO‑H563ZI 기반 전압·전류 계측 보드
사용·데이터 수신 가이드

처음 보드를 받은 사람도 펌웨어를 빌드·업로드하고, USB 또는 LAN에서 계측 데이터를 받을 수 있도록 현재 프로젝트 코드와 회로 PDF를 기준으로 정리한 오프라인 안내서입니다.

기본 전송: CSV / 10 Hz LAN: UDP 5000 보드 고정 IP: 192.168.0.50 디버그: ST‑LINK USB VCP
처음 15분하드웨어빌드·업로드USB 수신LAN 수신PC 연동 계약설정 변경패킷검증문제 해결

먼저 핵심만

이 시스템은 센서 실드 + NUCLEO‑H563ZI 조합입니다. 실드의 ADC가 전류/전압을 읽고, STM32가 원시 ADC 값을 보정·필터링해 USB 가상 COM과 LAN UDP로 동시에 보냅니다.

현재 펌웨어는 ADC를 약 4 ksample/s로 읽지만, PC에는 안전하고 다루기 쉬운 10 Hz의 최신 필터 결과를 보냅니다. 즉 LAN이 빠르다고 모든 RAW 샘플을 그대로 보내는 구조는 아닙니다. 통신 속도와 계측 품질은 분리해 둔 구조입니다.

가장 빠른 확인 경로: ST‑LINK USB로 펌웨어를 올린 뒤, NUCLEO의 RJ45를 PC와 같은 유선망에 연결하고 PC에서 UDP 5000을 열면 됩니다. 센서 입력을 아직 연결하지 않아도 “통신이 살아 있는지”는 확인할 수 있습니다.

1. 역할과 케이블 구분 2. 빌드와 SWD 업로드 3. USB 시리얼 수신 4. LAN UDP 수신 5. 소프트웨어 연동 답변 6. 자주 바꾸는 설정 7. CSV·Binary 패킷 8. 단계별 검증 9. 문제 해결

DRDY(Data Ready)는 ADC가 “새 변환값이 준비됐다”라고 알리는 하드웨어 신호입니다. 펌웨어는 DRDY 하강 에지에서 SPI DMA 수신을 시작하므로, 메인 루프에서 무작정 SPI를 폴링하지 않습니다.

1. 하드웨어와 케이블 역할

안전 우선: 이 문서는 PC 수신과 펌웨어 운용 방법을 설명합니다. 고전압·대전류·현장 전원을 연결하기 전에는 반드시 제공된 회로 PDF의 단자명, 절연 범위, 정격, 접지 방식을 실제 보드 리비전과 대조해야 합니다. 핀 이름만 보고 전원을 추정하거나, RAW/DAC 커넥터에 임의 신호를 넣지 마십시오.
구성품 / 포트역할처음 시험할 때 필요한가?주의
NUCLEO‑H563ZISTM32 MCU, ST‑LINK, RJ45 Ethernet이 있는 메인 보드필수센서 실드가 위에 적층되는 대상입니다.
NUCLEO ST‑LINK USBMCU 전원, SWD 디버그/플래시, Virtual COM Port필수PC와 연결하는 기본 USB입니다. 데이터가 흐르는 VCP도 이 경로입니다.
센서 실드 USB‑C 5 V센서 실드 아날로그 전원실드 동작 시험 시 필요회로 PDF상 NUCLEO의 3V3/5V/VIN과 실드 전원은 직접 묶이지 않습니다. 이 USB‑C를 ST‑LINK나 PC 데이터 포트로 오해하지 마십시오.
NUCLEO RJ45PC로 UDP 텔레메트리를 보내는 Ethernet 포트LAN 수신 시 필수센서 실드의 RAW 커넥터가 아니라 NUCLEO 보드의 RJ45에 연결합니다.
RAW / DAC 단자실드의 아날로그 신호·아날로그 출력 경로PC 데이터 수신에는 불필요PC용 RAW 디지털 데이터 포트가 아닙니다. MCU 디지털 데이터는 USB VCP 또는 UDP로 받습니다.

회로 PDF에서 확인된 계측 채널

  • I1, I2: 1 mΩ 샌트와 절연 증폭기 기반 전류 채널. 코드의 기본 표시 범위는 ±30 A입니다.
  • V1, V2: 고저항 분압과 절연 증폭기 기반 전압 채널. 코드의 기본 표시 범위는 ±250 V입니다.
  • ADC: ADS131M08, SPI + DRDY 방식. 펌웨어에서 ADC 채널 0~3을 I1, V1, I2, V2 순으로 처리합니다.
  • DAC: DAC8564 네 채널. 기본적으로 −FS/0/+FS를 약 0.5/2.5/4.5 V 등가 위치로 매핑합니다. 외부 장비를 연결하기 전 실제 파형을 계측기로 확인하십시오.

물리 연결 순서

  1. 전원이 모두 꺼진 상태에서 센서 실드를 NUCLEO의 Zio 커넥터(CN7~CN10)에 바르게 적층합니다.
  2. 첫 통신 시험에서는 현장 전류/고전압 입력을 연결하지 않습니다.
  3. NUCLEO의 ST‑LINK USB를 PC에 연결합니다.
  4. 실드의 아날로그 회로 시험이 필요한 경우에만 실드 USB‑C 5 V도 연결합니다.
  5. LAN 시험 시 NUCLEO의 RJ45를 PC 또는 같은 스위치에 연결합니다.

2. 빌드하고 펌웨어 올리기

프로젝트는 VS Code에서 열 수 있지만, 처음에는 터미널의 스크립트 경로를 권장합니다. 스크립트가 설치된 STM32Cube 번들에서 CMake, Ninja, Arm GCC, CubeProgrammer를 찾습니다.

필수 준비

  • Windows PowerShell
  • STM32CubeMX 또는 STM32CubeCLT 계열 번들(CMake, Ninja, Arm GCC 포함)
  • STM32CubeProgrammer 및 ST‑LINK 드라이버
  • Python 3.9 이상 (수신 도구용)

프로젝트 폴더는 이 문서가 있는 C:\stm32\COSMOKE_H563입니다. 사용자 이름에 한글이 있어도 빌드 스크립트는 임시 링크 파일을 프로젝트 아래 ASCII 경로에 두고, 플래시 스크립트는 C:\stm32\tools\programmer-*의 ASCII 경로 CubeProgrammer를 우선 사용하도록 구성되어 있습니다.

3. USB 시리얼로 먼저 받기

정의: 펌웨어 안의 COM1은 NUCLEO BSP가 가리키는 내부 논리 포트입니다. Windows의 COM1이라는 뜻이 아닙니다. PC에서는 장치 관리자에 보이는 STMicroelectronics STLink Virtual COM Port (COMx)의 실제 번호를 사용합니다.

한 번만 설치

python -m pip install pyserial

Windows 장치 관리자 → 포트 (COM 및 LPT)에서 ST‑LINK Virtual COM Port의 번호를 찾습니다. 예: COM3.

수신 시작

python .\Tools\cosmoke_serial_monitor.py COM3

기본 통신은 115200 bps, 8N1, CSV입니다. COM3은 장치 관리자에서 찾은 값으로 바꾸십시오.

정상 예시 (센서 미연결 상태일 수 있음) 
seq,ms,flags,adc_status,i1_mA,v1_mV,i2_mA,v2_mV,raw_i1,raw_v1,raw_i2,raw_v2,dac_i1,dac_v1,dac_i2,dac_v2,dropped,crc_error,spi_error,dac_error
0,0,0x0022,0x0000,0,0,0,0,0,0,0,0,32768,32768,32768,32768,0,0,0,0

0x0022에는 AFE_FAULT와 ADC_OFFLINE가 들어갈 수 있습니다. 센서 실드/ADC가 연결되지 않은 초기 시험에서 0 값이 나오는 것은 USB 통신 실패를 뜻하지 않습니다. 먼저 행이 10 Hz로 지속 수신되는지와 플래그를 확인하십시오.

4. LAN으로 UDP 데이터 받기

기본 펌웨어는 NUCLEO의 RJ45에서 100 ms마다 UDP datagram 하나를 보냅니다. USB는 디버깅·전원·보조 수신으로 두고, 현장 데이터 수집은 LAN으로 분리할 수 있습니다.

192.168.0.50보드 기본 고정 IPv4
255.255.255.0기본 서브넷 마스크
5000 / UDPPC가 듣는 목적지 포트
5001 / UDP보드 송신 소스 포트
중요: 기본 목적지는 255.255.255.255 (제한 브로드캐스트)입니다. 즉 같은 유선 L2 세그먼트의 수신 PC만 볼 수 있고, 일반적으로 라우터·VLAN·Wi‑Fi isolation을 넘어가지 않습니다. 첫 시험은 PC와 보드를 직접 연결하거나 작은 유선 스위치에 같이 연결하는 편이 가장 단순합니다.
1

RJ45 연결

NUCLEO‑H563ZI의 Ethernet RJ45를 PC Ethernet 포트 또는 동일한 유선 스위치에 연결합니다. Wi‑Fi만 연결한 상태로는 브로드캐스트를 못 받을 수 있으므로, 첫 시험에는 Wi‑Fi를 끄거나 우선순위를 낮추는 것이 좋습니다.

2

PC Ethernet에 임시 고정 IP 지정

Win + R → ncpa.cpl → Ethernet 어댑터 우클릭 → 속성 → Internet Protocol Version 4 (TCP/IPv4)에서 다음 값을 지정합니다.

항목값이유

서브넷 마스크255.255.255.0기본 펌웨어와 일치
기본 게이트웨이직결/전용 스위치면 비워 둠라우터가 실제로 192.168.0.1일 때만 입력

회사망이 이미 192.168.0.x를 사용하거나, 그 주소가 다른 장비와 충돌할 우려가 있으면 전용 스위치를 사용하거나 아래 “고정 유니캐스트” 설정으로 네트워크 계획을 바꾸십시오.

3

방화벽 경고가 나타나면 개인 네트워크에서 Python 수신을 허용합니다. 또는 Windows 방화벽에서 UDP 5000 수신을 허용하십시오.

4

데이터 확인

플래시 명령이 이미 리셋을 수행합니다. 수신기를 먼저 실행한 뒤 NUCLEO RESET 버튼을 누르거나 플래시 스크립트를 다시 실행합니다. 케이블을 부팅 후에 꽂아도 펌웨어가 물리 링크를 감지해 약 1초 간격으로 자동 활성화를 재시도합니다. 수신기에는 다음처럼 송신 보드 IP가 앞에 붙은 CSV가 표시됩니다.

Listening on 0.0.0.0:5000 (auto)
192.168.0.50,42,1234,0x0001,0x0000,1250,12000,-500,239000,...
수신 PC가 한 대로 정해졌다면: 브로드캐스트 대신 고정 유니캐스트

운영 환경에서는 수신 PC/서버를 정하고 브로드캐스트를 끄는 편이 더 예측 가능합니다. 예를 들어 PC를 192.168.0.100으로 쓸 경우 Core/Inc/app_config.h의 네 줄을 아래처럼 바꾼 뒤 빌드·업로드합니다.

#define APP_NETWORK_UDP_DESTINATION_0         (192u)
#define APP_NETWORK_UDP_DESTINATION_1         (168u)
#define APP_NETWORK_UDP_DESTINATION_2         (0u)
#define APP_NETWORK_UDP_DESTINATION_3         (100u)

수신 명령은 그대로 UDP 5000을 bind하면 됩니다. UDP는 연결형이 아니므로 PC 앱은 수신 포트 5000만 열면 됩니다.

DHCP를 쓰고 싶다면 (고급)

현재 기본값은 DHCP가 아닌 고정 IP입니다. DHCP가 있는 사내망에서 쓰려면 아래 매크로를 1u로 바꿔 빌드·업로드하고, 라우터/DHCP 서버에서 할당된 보드 IP를 확인하십시오.

#define APP_NETWORK_USE_DHCP                  (1u)

처음의 직결 시험에는 DHCP 서버가 없으므로 이 옵션을 켜지 마십시오. 주소를 확인하기 어려운 환경에서는 고정 IP가 더 빠르고 안정적입니다.

5. PC 소프트웨어 담당자에게 이렇게 전달하면 됩니다

“장비는 NUCLEO‑H563ZI Ethernet에서 UDP datagram을 10 Hz로 전송합니다. 기본 포맷은 ASCII CSV이고, PC 프로그램은 UDP 포트 5000에 bind해 한 datagram을 한 행으로 처리하면 됩니다. 기본 네트워크는 보드 192.168.0.50/24, 로컬 브로드캐스트 255.255.255.255:5000이며, 운영에서는 목적지를 수집 PC의 고정 IP로 바꿀 수 있습니다. USB ST‑LINK Virtual COM Port에도 같은 CSV를 115200 8N1로 미러링합니다. UDP이므로 재전송은 하지 않으며, sequence 필드의 불연속으로 유실을 감지합니다.”

인터페이스PC가 할 일기본값특징
LANUDP socket bind 후 datagram 수신UDP 5000, CSV, 10 Hz현장 데이터 경로. 비연결형이므로 packet loss 가능
USBST‑LINK VCP의 COMx를 115200 8N1로 열기CSV, 10 Hz디버그·가까운 거리 확인용. 전용 USB‑C가 부족할 때도 ST‑LINK 하나로 디버깅 가능
RAW 커넥터PC 소프트웨어 수신 대상 아님아날로그외부 계측/아날로그 신호용이며 디지털 프로토콜 아님

기본 CSV: 한 UDP datagram = 한 행

필드설명
seq, msADC 프레임 sequence와 MCU 시각(ms). sequence가 건너뛰면 ADC/전송 경로에서 프레임이 유실됐을 수 있습니다.
i1_mA, i2_mA필터 후 전류. 단위는 mA이므로 1250은 1.250 A입니다.
v1_mV, v2_mV필터 후 전압. 단위는 mV이므로 12000은 12.000 V입니다.
raw_*24-bit ADC 원시 signed count. PC가 직접 교정을 재현해야 할 때 참고용입니다.
dac_*0~65535 DAC code. 정상 0 단위 부근의 안전 중간값은 32768입니다.
dropped, crc_error, spi_error, dac_error펌웨어 누적 진단 카운터입니다. 0이 아닌 값이 계속 증가하면 하드웨어·SPI 신호 품질을 점검합니다.

실제 LAN 수신 한 줄 해석

아래는 실제 보드에서 정상 수신된 예입니다. UDP 모니터가 맨 앞에 붙이는 192.168.0.50은 송신자 IP 표시이며, 보드 펌웨어가 보내는 CSV 필드는 그 다음 648904부터 시작합니다.

192.168.0.50,648904,123030,0x0001,0x810F,11,-22,7,14,
3069,-609,1236,442,32778,32766,32774,32769,0,0,0,0
구간값해석
송신자 IP192.168.0.50UDP 모니터가 표시한 보드 주소입니다. 펌웨어 CSV 본문에는 포함되지 않습니다.
seq, ms648904, 123030ADC 프레임 번호와 부팅 후 시간(ms)입니다. 약 123.030초 시점의 샘플입니다. seq가 연속적으로 증가하는지로 ADC 프레임 흐름을 확인합니다.
flags0x0001VALID만 설정됐습니다. ADC 측정값이 유효하고, AFE/ADC/DAC/LAN 오류 플래그는 없습니다.
adc_status0x810FADS131M08이 제공하는 상태 워드입니다. 이 값은 기기 상태 추적용으로 함께 전송합니다. 이 예에서는 VALID 및 모든 오류 카운터 0과 함께 나타나므로 정상 획득 상태로 해석합니다.
필터 결과I1=11 mA, V1=-22 mV, I2=7 mA, V2=14 mV보정·필터를 거친 물리 단위입니다. 현재 입력이 0 근처이거나 미연결이면 이 정도의 작은 오프셋/잡음은 나타날 수 있습니다. 보정 전 정확도 판정값으로 사용하면 안 됩니다.
raw_*3069, -609, 1236, 442각 채널의 signed ADC 원시 count입니다. PC에서 자체 보정·분석을 할 때만 사용하고, 일반 표시에는 위 mA/mV 필드를 사용합니다.
dac_*32778, 32766, 32774, 32769DAC 출력 code입니다. 모두 중간값 32768 근처이므로 현재 계측값이 0 근처이고 출력이 안전 중심점에 가깝다는 뜻입니다.
오류 카운터0, 0, 0, 0dropped, crc_error, spi_error, dac_error 순서입니다. 이 부팅 구간에서 ADC 프레임 유실, ADC CRC 오류, SPI 오류, DAC 오류가 관측되지 않았습니다.
이 예의 결론: Ethernet UDP 수신, ADC 획득, 보정·필터, DAC 갱신이 모두 동작 중입니다. 다만 값이 실제 전류·전압의 정확한 절대값인지 판단하려면 승인된 기준 입력과 계측기로 영점·스케일 교정을 별도로 해야 합니다.

8. 테스트 순서와 확인 기준

통신만 확인 (입력 미연결)

  1. 빌드·플래시 후 USB monitor를 실행합니다.
  2. 10 Hz로 CSV 행이 들어오는지 확인합니다.
  3. LAN monitor도 실행해 같은 행이 들어오는지 확인합니다.
  4. 센서 미연결이면 ADC_OFFLINE, 0 값, DAC 32768이 나올 수 있습니다. 이는 안전한 대기값입니다.

도구 자체 단위 테스트

UDP 바이너리 디코더의 packet size, CRC 검증, 플래그 해석은 Python 테스트로 확인할 수 있습니다.

python -m unittest Tests.host.test_udp_monitor -v

이 테스트는 PC용 수신 도구를 검증합니다. 실제 센서 보정과 고전압 안전성 검증을 대체하지 않습니다.

센서 기능 시험 (승인된 저위험 입력부터)

  1. 회로 PDF와 실제 보드 리비전의 전원·절연·단자 표기가 일치하는지 확인합니다.
  2. 실드 전원과 ADC가 정상인지 USB/LAN의 flags로 먼저 확인합니다. VALID가 서고 ADC_OFFLINE이 없어야 합니다.
  3. 승인된 저전압/저전류 기준 소스를 한 채널에만 인가하고, CSV의 mA/mV 값과 기준 계측기를 대조합니다.
  4. 오실로스코프로 DAC 아날로그 출력이 0 단위에서 중간값 근처인지, 제한 시 범위를 넘지 않는지 확인합니다.
  5. 그 뒤에만 채널을 늘리고, 실제 부하/고전압 시험은 별도 안전 절차와 승인 아래 진행합니다.

9. 문제 해결

CubeProgrammer가 Unable to list supported devices 또는 device identify 오류를 보임
  1. 우선 스크립트로 1 MHz SWD 연결만 확인합니다.
    powershell -ExecutionPolicy Bypass -File .\Tools\Flash-Firmware.ps1 -ConnectOnly
  2. ST‑LINK USB 케이블, NUCLEO 전원 LED, 장치 관리자 ST‑LINK 인식을 확인합니다.
  3. 사용자 프로필의 한글 경로에서 CubeProgrammer DB를 찾지 못하는 경우가 있습니다. 이 프로젝트의 플래시 스크립트는 C:\stm32\tools\programmer-* ASCII 경로를 우선 탐색합니다. 그 경로에 CubeProgrammer 복사본이 있는지 확인하십시오.
USB에서는 보이는데 LAN에서 아무 것도 안 보임
  1. NUCLEO RJ45에 케이블이 꽂혔는지와 링크 LED를 확인합니다.
  2. PC 유선 Ethernet이 192.168.0.100 / 255.255.255.0인지 확인합니다. Wi‑Fi만 연결하지 않았는지도 확인합니다.
  3. 수신기를 보드 리셋 전에 먼저 실행합니다.
    python .\Tools\cosmoke_udp_monitor.py --bind 0.0.0.0 --port 5000
  4. Windows 방화벽에서 Python 또는 UDP 5000 수신을 허용합니다.
  5. 회사 라우터/VLAN/Wi‑Fi isolation을 통한 브로드캐스트는 기대하지 마십시오. PC와 보드를 같은 전용 유선 스위치에 연결해 재시험합니다.
값이 0이고 0x0022 같은 플래그가 계속 보임

PC 데이터 경로 자체는 정상일 수 있습니다. 0x0020(ADC_OFFLINE)나 AFE fault가 포함된 상태이며, 센서 실드 미연결, 실드 전원 미공급, ADC/SPI 초기화 실패가 원인일 수 있습니다. 입력을 무리하게 연결하지 말고 실드 적층, 전원, DRDY/SPI 핀 매핑과 회로 PDF를 점검하십시오.

USB 시리얼 포트가 보이지 않음

실드 USB‑C가 아니라 NUCLEO ST‑LINK USB를 PC에 연결했는지 확인합니다. 충전 전용 케이블이 아닌 데이터 케이블을 사용하고, 장치 관리자에서 ST‑LINK 드라이버를 확인하십시오.

LAN은 빠른데 왜 10 Hz만 보냄?

기본 10 Hz는 PC 표시·로깅을 위한 텔레메트리 주기입니다. 내부 ADC 획득과 필터는 별도 경로로 더 빠르게 동작합니다. 무작정 주기를 줄이기보다 APP_TELEMETRY_PERIOD_MS를 단계적으로 조정하고, sequence/flags/CPU 부하/수신 손실을 함께 검증하십시오. UDP는 신뢰성 보장 프로토콜이 아니므로 고속 로그에서 sequence gap을 처리해야 합니다.

  • ADC 획득·변환·DAC·텔레메트리·LAN 전송을 역할별로 분리했습니다.
  • 유효하지 않은 ADC 상태에서는 DAC를 안전 중간값으로 유지하고 상태 플래그를 전송합니다. 다만 SENSOR_FAULT_N은 소프트웨어 polling 입력이므로, 이 펌웨어만을 하드웨어 보호 인터록으로 간주하면 안 됩니다.
  • ADC 재초기화 전에 진행 중인 SPI DMA를 중단하고 ADC chip-select를 해제하도록 보완해, 복구 중 SPI1 재사용 경합을 줄였습니다.
  • LAN은 최신 프레임만 보관하는 mailbox 방식이므로, 네트워크가 잠시 늦어도 계측 루프에 대기열이 쌓이지 않습니다.
  • Ethernet MAC은 MCU UID 기반 locally-administered unicast 주소로 생성해 동일한 고정 MAC 충돌을 피합니다.
  • NetX Duo의 Target 설정 헤더가 실제 빌드에서 우선 적용되도록 include 순서를 바로잡고, Ethernet 패킷/스레드 동작에 맞춰 NetX 메모리 pool을 64 KiB로 확보했습니다.
  • LAN 케이블이 없는 상태로 부팅하더라도 IP helper가 5초 동안 막히지 않게 하고, 케이블이 나중에 연결되면 link-enable을 자동 재시도하도록 보완했습니다.
  • UDP 수신 도구의 CRC/포맷 검증 테스트를 추가했습니다.
  • 현재 USB VCP 출력은 계측 thread에서 최대 20 ms까지 대기할 수 있습니다. 4 kSPS 실기 시험에서는 dropped 및 CRC/SPI 카운터가 증가하지 않는지 반드시 확인하고, 고속화를 요구할 경우 UART DMA/별도 송신 thread를 다음 개선 단계로 검토하십시오.
운영 전 최종 체크: (1) USB와 LAN 모두에서 행 수신, (2) flags에 ADC/DAC/LAN 오류가 없는지, (3) 기준 입력 대비 보정값, (4) DAC 출력 파형/범위, (5) 수신 프로그램의 sequence gap 처리, (6) 실제 네트워크에서 브로드캐스트 대신 유니캐스트 사용 여부를 확인한 뒤 현장 계측으로 넘어가십시오.
